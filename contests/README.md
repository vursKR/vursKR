# contests/

공모전 1건 = 디렉토리 1개. 상태의 단일 진실원은 Notion 「공모전 트래커」이고, 여기는 산출물과 로그만 둔다(wayfinder 맵 결정: `docs/agents/issue-tracker.md`와 이슈 #8 참고).

디렉토리 이름은 `<발주처-슬러그>-<공모전-슬러그>` 형식을 쓴다. 예: `gicheongyeongbu-junyoung-idea/`.

## 디렉토리 안의 파일

공모전 진행 단계에 따라 파일이 하나씩 늘어난다. 없는 파일은 그 단계에 아직 도달하지 않았다는 뜻이다.

| 파일 | 단계 | 내용 |
|---|---|---|
| `notice.md` | ①탐색 | 공고 원문(마감, 발주처, 상금, 배점표 URL 또는 "미공개") |
| `filter.md` | ②선별 | 하드 필터 8종 통과 여부와 100점 스코어링 결과, 근거 |
| `recon.md` | ③정찰 | 발주처 기존사업 40건 이상, 배점 만점 조건 문장, 실격 조항, 과거 수상작 |
| `seed.md` | ④착안 | 착안 브리프(사람이 아이디어를 확정한 기록) |
| `ledger.md` | ⑤작성 | 수치 원장. 규약은 `evals/contract.md` |
| `draft.md` | ⑤작성 | 응모작 본문 |
| `redteam.md` | ⑥검증 | 레드팀 리포트(기계 판정 + LLM 판정 A/B/C), 개정마다 반영 검증 이력 |
| `submission/` | ⑦제출 | 제출 패키지(문서 파일, 접수 정보). 실행 로그 포함 |
| `result.md` | ⑧학습 | 결과, 자체채점과 실제 결과의 괴리, 오류 체크리스트 갱신분 |

## seed.md 서식

④착안 브리프는 후보를 만들지 않는다. 아이디어 확정은 G1에서 사람이 한다(지시서 6-2, 착수 보고서 §3-9 결정). 절 4개로 고정한다.

| 절 | 내용 | 분량 |
|---|---|---|
| `## 정찰 요약` | ③정찰이 찾은 발주처 기존사업 중 이 공모전과 겹치는 것, 과거 수상작의 공통 골격 | 15줄 이내 |
| `## 배점 만점 조건` | 배점 항목마다 "만점을 주려면 문서에 무엇이 있어야 하는가"를 한 줄씩. 공고 문장을 인용한다 | 배점 항목 수만큼 |
| `## 죽은 후보` | 하드 필터나 실격 조항에 걸려 이미 배제한 방향과 그 사유. 사람이 같은 길을 다시 밟지 않게 한다 | 걸린 만큼 |
| `## 착안 질문` | 사람에게 묻는 질문 5개까지. 답이 곧 아이디어가 되도록 구체적이어야 한다 | 5개 이하 |

## 실행 로그

모든 무인 실행은 각 단계 파일 하단에 `## 실행 로그` 절로 무엇을 언제 왜 했는지 남긴다(지시서 6-1).
